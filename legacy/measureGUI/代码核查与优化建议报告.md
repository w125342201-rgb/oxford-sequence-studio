# TeslatronPT 测量程序核查与优化建议报告

**核查对象**
- `measureGUI/teslatronpt_iv_gui.py` — I‑V 程序（超导临界电流 Ic 测量）
- `measureGUI/teslatronpt_rt_gui.py` — R‑T 程序（超导转变温度 Tc 测量）
- 依赖：`oxford/oxford_teslatronpt_api.py`、`keithely6221_2182A/keithley_6221_2182a_driver.py`

**核查方式**：逐行静态代码审查 + 跨文件依赖验证（导入路径解析、驱动层 SCPI 命令、输出使能、Delta 数学模式）。已用受管 Python 实测导入解析，确认第 1 条缺陷为实锤。

---

## 〇、总体结论

两个程序整体架构合理（驱动/界面分离、队列跨线程通信、停测 `InterruptedError` 处理、滞回气压、固定量程/固定 NPLC 提升精度等设计都已具备）。但**存在 5 个严重缺陷**，其中 4 个属"阻断级"（程序起不来或测不出有效数据），1 个属"数据错误级"。最致命的是两个 GUI 顶部 import 仍用**重构前的扁平模块名**，而仓库已把模块移入包内——**两个程序根本无法启动**（实测 `ModuleNotFoundError`）。其次 I‑V 缺一个 GUI 变量、DC 模式全程未开电流输出、驱动未设 `DELT:MATH` 导致 DELTA 数值整体错误。

> ⚠️ 下述改动均涉及真实低温/强磁仪器控制逻辑，建议在确认仪器 `DELT:MATH` 出厂默认后再落地（见缺陷 4）。本报告给出可直接套用的修复片段。

### ⚠️ 最高优先级：6221+2182A Delta 通讯铁律（2026‑08‑31 确立，违反会重引入 -113）

本报告及所有后续改动**必须以官方为准**：权威源 = Tektronix 官方 `Delta_Measurement_Example.py` + 6221/2182A 手册 + PyMeasure `keithley6221.py` 源码。**本地文档/记忆若与官方冲突，一律以官方为准。**

Delta 模式架构（已与官方例程核对，绝非推测）：
- **6221 是 master，2182A 是从机**。主机**只与 6221 通讯**（GPIB）；2182A 的全部控制经 6221 的 `:SYST:COMM:SERIAL:SEND` 串口链路 + Trigger Link 内触发，主机**没有**对 2182A 的独立写通道（Delta 下 2182A 的 GPIB 通道闲置）。
- **DC 模式**（I‑V）下 2182A 是独立台式电压表，主机经其 GPIB 直连读数——与 Delta 拓扑完全不同，勿混。
- **高速参数**：单个电流脉冲最短 50µs（非 50ms）；2182A Delta 读取率上限 ≈24 Hz（≈42ms/读数）。

**严禁写入 2182A 串口的命令（违反即 -113 且只亮面板不进日志）**：
1. `:SYST:ERR:CLE` —— 2182A 根本无此命令，`-113 "Undefined header"`。
2. `:SYST:COMM:SER:`（缩写）—— 必须用全拼 `:SYST:COMM:SERIAL:`（缩写在本固件 `-113`）。
3. `BAUD` / `FLOW`（串口参数）—— 官方例程不发，链路用仪器默认配置；发送会导致每组合 -113。
4. `:TRIG:SOUR` 任意值 —— 6221 是 master，经 Trigger Link 内部触发 2182A；设 TLINk/EXT/IMM 都会破坏测量。
5. `:SENS:AVER:WIND/TCON/STAT/COUN` —— 这些是 **6221 自己的命令**（官方例程直接发给 6221），**绝不**经串口转发给 2182A（2182A 不认识 `:SENS:AVER:WIND` → -113）。

**Delta 下 2182A 串口只允许这两条**（`setup_delta` 的 `configure_2182` 块）：`:SENS:VOLT:NPLC <n>`、`:SENS:VOLT:RANG <v>`（**固定量程，禁用 AUTO**——HIGH/LOW 两次读数若各触发自动量程，差值被毁）。历史上曾发过的 `*RST` 已于 2026‑08‑31 **删除**（冗余：每 combo 重设 NPLC+固定 RANG 已覆盖陈旧态、`:SOUR:DELT:ARM` 每次重建链路）。

**手动 "Reset instruments" 按钮（Delta 模式）**：**不**对 2182A 发任何命令（含 `*RST`），仅复位 6221。详见缺陷 16。

### 2. 【阻断·I‑V】`electrical_mode_var` 全程未定义，连接即崩溃
- **位置**：使用处 `_connect_worker` L524、`_set_current_and_read` L825、`start_measurement` L978；定义处：**无**（`__init__` 未创建该 `StringVar`，UI 也无 DC/DELTA 单选）。
- **现象**：`__init__` 启动的守护线程 `_connect_worker` 到 L524 抛 `AttributeError` → 被 `except` 捕获并 `put(("error", ...))`，`device_ready` 永远 `False`，点击 Start 恒报 "Not connected"。**整 I‑V GUI 不可用**。
- **对比**：R‑T 在 L139 正确定义 `self.electrical_mode_var = tk.StringVar(value="DELTA")`。
- **修复**：`__init__` 增加变量 + UI 单选（效仿 R‑T L139/L297‑309），并在 `start_measurement` 守卫 2182A 配置（见缺陷 5）。

### 3. 【阻断·I‑V·DC 模式】整段电流扫场期间输出从未开启 → 测得零电流
- **位置**：`_measurement_worker` L1058、扫场循环 L1115/1123/1136/1162，`_set_current_and_read` L835。
- **根因**：驱动 `Keithley6221.set_current()`（L314）**只写 `:SOUR:CURR`，不开启输出**；输出由独立 `output_on()/output_off()` 控制（L333‑337）。I‑V 在 L1058 `output_off()` 后，**扫场全程再无 `output_on()`**（仅 DELTA 路径靠 `run_delta_once` 内部自行开启）。
- **后果**：DC 模式下 6221 输出关闭，样品上无电流，2182A 读到 ~0 V/噪声 → 保存的是假 I‑V 曲线。R‑T `_measure_dc`（L832）明确 `output_on()`，唯独 I‑V 漏掉。
- **修复**：L1058‑1059 之后、温度循环前开启输出：
```python
self.src.output_off()
self.src.set_current(0.0)
self.src.output_on()          # ← 新增：使后续扫场真正输出电流
```
（DELTA 路径由 `run_delta_once` 自行管理输出，此行无害。）

### 4. 【数据错误·两程序共享】驱动未设置 `DELT:MATH`，Trace Buffer 返回电阻而非电压
- **位置**：`keithely6221_2182A/keithley_6221_2182a_driver.py` → `setup_delta`（L433‑439）。写入了 `HIGH/LOW/DELAY/COUNT/CABORT/CSWITCH`，**从未写 `:SOUR:DELT:MATH`**。
- **根因与后果**：6221 的 `DELT:MATH` 出厂/复位默认通常为 **RES**（电阻）模式；此时 `:TRAC:FEED CALC1` 的 Trace Buffer 返回 **R = VΔ / (HIGH−LOW) = VΔ / (2I)**，单位 Ω，**不是电压**。而两个 GUI 都**假设**返回的是电压 VΔ：
  - R‑T `_measure_delta`（L883‑888）：`resistance = voltage_delta / (2.0*current)`，并把该值当"电压"存入 `delta_voltage_V` 列 → 实际是电阻再除以 2I，**量级与单位全错**。
  - I‑V `_measure_delta_point`（L814‑815）：`voltage = 0.5*vdelta; resistance = voltage/current` → 同样错。
- **修复（最小确定性改动，同时修好两程序）**：在 `setup_delta` 写入 `DELT:*` 之后显式设数学模式，使 Trace 返回真正的 VΔ，匹配现有 `VΔ/2` 重建：
```python
self.write(":SOUR:DELT:MATH VOLT")   # CALC1 返回 V(HIGH)-V(LOW) = VΔ
```
> 若不希望依赖仪器默认，此为**必须显式设置**的确定性修复。若改为 GUI 直接按 RES 处理（R=trace、V(I)=R·I），需同步改两处重建公式；推荐前者（改动面最小）。

### 5. 【交互崩溃·R‑T】`_on_electrical_mode_changed` 引用未定义的 `visa_hint_var`
- **位置**：L530‑540；`visa_hint_var` 在 `__init__` 中**未定义**，UI 也无对应 Label。
- **现象**：点击 DC/DELTA 单选触发回调，`self.visa_hint_var.set(...)` → `AttributeError`，GUI 报错。连接/测量不受影响，但模式切换交互直接崩溃。
- **修复（二选一）**：
  - 方案 A（推荐）：`__init__` 中 `self.visa_hint_var = tk.StringVar(value="DELTA：实际只使用 6221 GPIB；2182A 地址可留空")`，并在 VISA 段下方加 `ttk.Label(visa_frame, textvariable=self.visa_hint_var)`；
  - 方案 B（最简）：删除回调中两行 `visa_hint_var.set(...)`，改成 `self.log(...)` 提示。

### 16. 【健壮性增强·两程序】独立 "Reset instruments" 按钮：仅复位 6221，Delta 下不碰 2182A
- **位置（新增）**：两程序均新增 `_reset_instruments()` 方法，由独立 **"Reset instruments" 按钮**手动触发（2026‑08‑28 20:24 起已取消测量前自动调用）。
- **动机**：上一次运行（尤其 DELTA 路径）若异常中断、手动停测或遇错误，6221 可能残留已 arm 的 Delta 序列、未关闭的输出、固定的电流/电压量程或错误队列残留（`-370` 等）。这些残留若带入下一次正式测量，会导致 Delta 无法重新 arm、读数异常或电流量程错乱。手动 Reset 可彻底清掉 6221 状态，使后续运行从干净起点开始。
- **设计要点（2026‑08‑31 按官方铁律收敛）**：
  1. **仅复位 6221 测量电子学，不复位 Oxford Mercury 控制器（温度/磁场）**——温度与磁场是慢变量、且实验中途复位会破坏已建立的温场/磁场，故明确排除。
  2. **6221**：`*RST` 后 `:SYST:ERR:CLE`（均为 6221 自有合法命令）清错误队列。
  3. **2182A 仅在 DC 模式复位**：当独立 VISA 句柄存在（`self.dmm is not None`）时直连 GPIB `*RST`+清错误（此时 2182A 是台式电压表，复位合理）。
  4. **⚠️ Delta 模式（2182A 为 6221 从机）下，主机不对 2182A 发任何命令（含 `*RST` / `:SYST:ERR:CLE`）**——这是 2026‑08‑31 按用户"Delta 下 2182A 由 6221 接管、主机不直控"的架构结论删除的。**严禁**再把 `send_to_2182("*RST")` / `send_to_2182(":SYST:ERR:CLE")` 加回来：前者冗余、后者是 `-113` 未定义头，且串口单向、错误只亮 2182A 面板不进日志。2182A 的状态由 `:SOUR:DELT:ARM`（每 combo 重建）与 `setup_delta` 的 NPLC+固定量程两条命令管理。
  5. 复位后强制 `output_off()` + `set_current(0.0)`，并把电流量程/顺从电压重新设为本次测量的目标值——`*RST` 会把 `:SOUR:CURR:COMP` 清回默认（约 0.1 V），故 Reset 后必须重新断言 compliance 105 V。
- **实现片段（两程序一致，当前实际代码）**：
```python
def _reset_instruments(self):
    """Reset the Keithley measurement electronics to a clean state.

    Called by the manual "Reset instruments" button only (NOT auto before
    Start). Resets the 6221; resets the 2182A ONLY in DC mode (direct GPIB).
    In Delta mode the 2182A is a 6221 slave and is intentionally NOT touched.
    """
    try:
        self.src.reset()              # 6221 *RST
        self.src.clear_errors()       # 6221 :SYST:ERR:CLE  (valid for 6221)
        self.put(("log", "6221 reset (*RST) done."))
    except Exception as exc:
        self.put(("log", f"6221 reset warning: {exc}"))

    if self.dmm is not None:
        # DC mode: 2182A is a standalone voltmeter on its own GPIB link.
        try:
            self.dmm.reset()
            self.dmm.clear_errors()
            self.put(("log", "2182A reset (*RST) done."))
        except Exception as exc:
            self.put(("log", f"2182A reset warning: {exc}"))
    else:
        # Delta mode: 2182A is 6221-controlled; host sends NOTHING to it here.
        self.put(("log", "Delta mode: 2182A is 6221-controlled; not reset directly."))
    try:
        self.src.output_off()
        self.src.set_current(0.0)
    except Exception:
        pass
```
- **调用位置**：按钮处理 `reset_instruments()`（校验连接/测量状态）→ 后台线程 `_reset_worker()` → `_reset_instruments()`，随后重设 compliance 105 V。Start 时不再自动复位，仅重设量程与 compliance（DC 模式额外重配 2182A 量程/NPLC）。

### 9. 【文档误导·R‑T】SWEEP 模式并非"连续扫温"
- L1009‑1090：SWEEP 仅比 STEP 多 `configure_temperature_ramp(enabled=True)`，但每温度点仍 `_wait_temperature_stable` 逐点等待稳定——本质仍是离散逐点测量，仅点间过渡用斜坡（减小热冲击）。
- **建议**：文档/UI 说明改为"斜坡过渡的逐点扫描"，避免误以为温变中连续采集（连续采集需改 `_wait_temperature_stable` 为沿斜坡采样）。功能本身无错，属预期管理。

### 10. 【数据语义不一致·R‑T】`delta_voltage_V` 列在 DC 模式下实为直流电压
- `_measure_dc` 返回 `voltage`（DC 直读）写入 `point.voltage_v`；`_measure_delta` 返回 VΔ。同列"delta_voltage_V"两模式含义不同。
- **建议**：拆分为 `voltage_V`（DC）与 `delta_voltage_V`（DELTA）两列，或增加 `electrical_mode` 列并注释，便于后续 Tc/R(T) 拟合。
