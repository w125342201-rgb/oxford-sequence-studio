# 文档导航

本项目文档分三层，**效力严格不同**。任何修改前请先读第 0 层。

| 层 | 目录 / 文件 | 性质 | 能否作为依据 |
|---|---|---|---|
| **L0 规范** | [开发规范.md](开发规范.md) | **唯一权威**：边界、红线、契约、流程、决策台账、冲突裁定 | ✅ 唯一依据 |
| **L2 参考** | [reference/](reference/README.md) | 说明性文档（11 篇）：架构、硬件、原理、格式、测试… | ⚠️ 仅解释；冲突以 L0 为准 |
| **L3 历史** | [archive/](archive/README.md) | 1.6.0–1.7.7 的原始报告与测试输出（冻结，不改写） | ❌ 只作证据 |
| 使用者入口 | [../README_使用说明.md](../README_使用说明.md) | 面向操作者的版本说明 | 操作参考 |

## 1. 我该先读什么

| 你的目的 | 读法 |

| 第一次接手 | [开发规范](开发规范.md) §1–§5 → [reference/01](reference/01-项目概览.md) → [reference/02](reference/02-架构与模块.md) |

## 2. 三条硬规则

1. **规范优先**：其他文档与 [开发规范](开发规范.md) 冲突，一律以规范为准；发现冲突按规范 §12 登记。
2. **台账先行**：任何新方案先查规范 §8。状态为 `否决（R-）` / `撤销（W-）` 的，不得重新实施。
3. **历史不是需求**：[archive/](archive/README.md)（含其中 `.workbuddy/memory/` 的其他 agent 记忆）里的"待办 / 建议"只是当时的想法，不构成需求（规范 §0.3）。

## 3. 目录结构

```
docs/
├── README.md            ← 本文件（导航）
├── 开发规范.md          ← L0：唯一权威
├── plans/               ← 工作稿：待批准的修改计划（非规范，实施后转成规范 §13 记录）
├── reference/           ← L2：说明性文档（01–11，均带从属声明）
│   ├── README.md
│   ├── 01-项目概览.md … 11-版本历史.md
└── archive/             ← L3：历史原件（冻结）
    ├── README.md
    ├── CHANGELOG_1.6.7.md … VALIDATION.md（14 份报告）
    └── evidence/        历史测试输出 test_results*.txt（7 份）
```

## 4. 维护约定

- 新增文档：先判断属于哪一层；说明性文档放 `reference/` 并在其 README 登记一行；待批准的改动方案放 `plans/`。
- 计划转正：`plans/` 里的方案实施后，必须把结论写进规范 §8 台账与 §13 变更记录，计划文件保留为过程记录（可移入 `archive/`）。
- 改历史文件：**不允许**。需要说明时，在 `archive/README.md` 追加"后续说明"，原文保持原样。
- 每次行为变更：必须同时更新 [开发规范](开发规范.md) 的对应章节与 §13 变更记录（模板见规范 §11.4）。
