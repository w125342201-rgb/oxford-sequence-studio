# Oxford Sequence Studio 1.7.5：长跑状态与恢复修复

2026-10-21，基于用户提供的《1.7.4 逻辑缺陷与冗余审查报告》逐项复核后修改。

**继续保留：源顺从、过温、关键源设置异常触发整轮失败及清理。** 普通无效读数仍按既有规则写 NULL 后继续。没有删除矩阵切换前的真实关源确认。

## P0 / P1 修复

| 报告项 | 实现 |
| --- | --- |
| P0-1 磁场判据不一致 | 后端把本步骤 tolerance 传给驱动。驱动返回实际磁场、ACTN、arrival_verified、started、no_op_ramp 及设定/启动尝试信息；完整结果写入 set_environment 事件。无运行励磁且实际磁场超出本步骤容差时，引擎明确失败，不再把历史 12 mT 启发式范围当成测量到位。 |
| P0-2 角度超差毒化会话 | 首次超差或回读失败后停止自动角度查询，但温压磁场监控继续。角度步骤保持等待，禁止未确认时采集和切换电极。运行中可人工确认静止后请求一次复核，由原仪器工作线程执行。停止后可人工确认当前静止位置并解除旧目标，再设置新目标，无需断开重连。 |
| P0-3 禁用节点校验 | 禁用节点及其后代不参与运行范围、电流、离散设定和交叉条件校验。结构、字段、ID、基本类型/有限数值、已删除功能仍校验。重新启用后恢复完整运行校验。 |
| P1-1 日志 | 环境等待开始及之后每约60秒写 environment_wait；记录 axis、目标、实际值、状态、经过时间、节点路径和角度异常。运行失败保存完整 traceback 到 failure/run_end 事件及 run.json；清理失败也保存调用栈。 |
| P1-2 采集前环境中断 | 保持“环境健康后才开始新采集”的原规则，不盲目跳点。每次重试写 io_wait，界面显示已等待分钟数，可暂停/停止；采集后环境失败仍保留已取得电压并标记环境缺失。 |
| P1-3 关源确认 | 关源命令仍真实执行。OUTP? 最多查询3次，失败之间间隔0.1秒。仅 OFF 或有限数值零视为关闭（支持0.0）；异常文本不猜测解析，写入日志。三次仍不确认，或任一关源命令出错，仍失败并禁止切换矩阵。 |

不自动执行 RTOZ→RTOS，不把12 mT宣称为硬件最小步长，不自动放宽磁场容差。小步进的实际能力仍需要实机核对。磁场已到测量容差内时允许等待稳定后采集，无需证明曾经历长时间RTOS。

## 角度恢复操作

1. 新增配置 rotation_margin_s，默认1.5秒，加入预计运动时间后的静默等待；旧方案自动补此字段。
2. 运动期间仍禁止查询。预计等待结束只自动查询一次；若超差或通信失败，显示等待人工角度校验。
3. 确认机械已停止后，点击“确认静止后复核角度”。运行中的请求通过 Event 交给工作线程，UI不操作仪器。
4. 若复核到位，原角度步骤继续稳定等待再采集；仍超差则保持等待，不重复发送运动命令。
5. 若实际停在另一角度且需重设目标，先停止序列，再点击“停止后解除未完成角度目标”，确认静止并成功回读后解除旧目标。不会把旧目标当成已完成。

## P2 修复与优化

| 报告项 | 实现 |
| --- | --- |
| P2-1 3f假冲突 | 连续PXI设置比较仅包含当前附加谐波的相位。3f不因隐藏2f相位不同而拒绝，反之亦然；新建/迁移默认值归属明确。 |
| P2-2 隐藏字段 | 表单仅解析当前可见字段；隐藏字段保留原有存储值，不读取隐藏输入框中的残留文本。 |
| P2-3 点编号 | 增加明确 acquisition_index、acquisition_count、csv_row_count 和计数语义元数据；绘图横轴可选 logical_point 或 acquisition_index。保留旧 point/points 作为兼容别名，不静默改变历史含义。 |
| P2-4 未完成环境状态 | 电极组合未测完时表级 environment_status=incomplete；已测电极的 routeN_environment_status 仍表示该电极自己的真实状态。 |
| P2-5 实时图 | 用deque(maxlen=20000)代替逐点切片。自动刷新最多约4次/秒，每次只处理最近3000次采集，界面明确标注范围；大曲线不再为每个顶点额外画圆点。文件仍保存全部数据。 |
| P2-6 Delta配置 | 同一运行中参数不变时复用已经核验的2182A NPLC/固定量程，省略两次2秒的重复设置等待。每点仍回读参数，复用时额外确认固定量程状态；仍重新配置6221、清旧事件、清trace、重新arm并等待完成。错误/停止、暂停、重连、新运行、切换AC后清缓存。 |
| P2-7 温度速率 | 配置上限限制为 (0,100] K/min，与现有驱动约束一致。 |
| P2-8 手动入口 | 手动步骤拒绝空数据目录；关源/HOLD按钮明确标为“停止序列并关源 / 磁场HOLD”。 |

Delta优化只减少每次复用时4秒的固定配置等待，额外核验仍耗通信时间，不承诺报告中估计的总机时。未缩短arm、源滤波、输出隔离等等待，未取消每点安全验证。底层独立调用 run_delta_once 默认不启用复用；Studio 后端启用受核验的复用。

## 冗余与报告中不宜直接删除的项目

已清理未使用的scroll_panel、content_split、env_time，表格只显示当前模式相关参数。Delta begin不再额外重复设置compliance。自动温压策略的模拟后端复用同一个ThermalRule；service近期取得的probe读数可用于紧接着的snapshot，避免一次重复查询。旧marker缺字段统一按历史0°处理，新建节点的显式90°保持。angle_read_time_unix现在进入CSV和逐电极详情列。

以下保留而非按报告字面删除：

- 跨层关源确认、PXI禁止矩阵切换的运行期防御；不能用软件状态缓存替代硬件确认。
- Engine.state供测试/诊断使用；check_currents的既有调用签名保持兼容。
- visible_fields中的measurement_device分支供全局配置表单使用，确实可达。
- 历史方案升级链保持可追溯；不为精简代码重写旧版本迁移语义。
- 校验与清单生成可再次遍历声明树；循环乘数不会实际展开成十万节点，不能把十万采集次数当成十万树节点。
- events记录一次采集，宽表记录一轮电极组合，所以environment_timing不同是明确的记录粒度差异；逻辑行不冒充某一个route_index。

## 数据兼容与对账

- run.json：points保留为采集次数别名，新增acquisition_count；csv_row_count包含最后可能未完成的一行。counter_semantics说明各字段含义。
- events：point仍为逐次采集编号，同时明确写acquisition_index；logical_point用于与宽表关联。
- data.csv：point仍为logical_point别名；直接接线/PXI行包含acquisition_index；逐点电极表的每个routeN_acquisition_index对应那次采集，公共acquisition_index留空。
- CSV新增acquisition_index、angle_read_time_unix，逐电极详情亦增加二者。标准PXI四通道双谐波CSV现在为50列，读取脚本请使用列名。
- 日志恢复工具保留上述编号与角度回读时间，输出逐次采集长表，不覆盖原表。
- 普通无效电压仍为NULL，未完成电极仍为空白；源异常仍按用户要求停止整轮。
