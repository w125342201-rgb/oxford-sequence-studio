# 10 · 开发指南

> **本文是说明性参考，不是规范。** 规范效力与唯一权威以 [开发规范](../开发规范.md) 为准；本文与规范冲突时，以规范为准并应在规范 §12 登记冲突。

## 1. 环境准备

```powershell
# 只需标准库即可跑模拟模式（Tkinter 随 Python 安装）
python --version          # 需 ≥ 3.10

# 实机依赖（模拟模式不需要）
python -m pip install -r requirements.txt   # pyvisa / pyserial / numpy / nidaqmx

# 建议：始终以 UTF-8 模式运行（见 09 §2）
$env:PYTHONUTF8='1'
```

启动：`python main.py` 或 `start_windows.bat`（优先 `py -3`，失败回退 `python`；出错会 `pause`）。

## 2. 修改代码时必须守住的六条

1. **字段集封闭**：`SPECS[kind]` 决定该节点合法的参数字段；`CONFIG` 决定合法配置字段。增删字段必须同步：
   `SPECS`/`CONFIG` → `validate()`/`validate_config()` → `LABELS`/`CONFIG_LABELS` → `upgrade_document()` 的默认值补齐 → 测试。
   只改前两处会让**所有旧方案无法载入**。
2. **默认值单一来源**：默认值引用模块常量（`FIELD_MAX_RATE_T_PER_MIN` 等），不要第二次写 `0.237` 字面量。
3. **单线程碰仪器**：UI 想操作仪器必须走 `App.submit()` 或置 `Engine` 的 Event，不能在 Tk 回调里 `backend.xxx()`。
4. **fail-closed**：关源、矩阵切换、旋转检查失败一律抛错；不要"记个日志然后继续"。
5. **先落盘后通信**：`record()` 里 `acquisition` 事件必须早于环境回读；调整顺序会破坏恢复能力。
6. **不改 legacy 算法**：`legacy/` 是原样保留的对照基线（`original_sources_sha256.json` 可校验）。要改算法，先在 `studio/` 层包装并补测试。

## 3. 常见改动配方

### 3.1 新增一种节点类型

```
① SPECS[kind] = ('中文标签', {参数默认值})
② 若可含子步骤 → CONTAINERS 加入
③ LABELS 补参数中文名
④ validate() 里加类型/范围/交叉规则分支
⑤ Engine.execute() 里加分派分支（或进 measurement()）
⑥ workload() 里给计数语义（operations/acquisitions/csv_rows）
⑦ instrument_options.visible_fields() 若需要按设备隐藏参数
⑧ GUI：SPECS 自动出现在下拉框；如需专用控件再改 Form
⑨ tests：至少覆盖"能执行""非法参数被拒""计数正确"
```

### 3.2 新增一个配置项

```
① CONFIG[key] = 默认值
② validate_config() 加类型/范围校验（布尔/数值/字符串自动分支，特殊规则手写）
③ CONFIG_LABELS[key] = 中文名（否则设置窗口显示英文键名）
④ upgrade_document() 里 config.setdefault(key, 默认值)   ← 必须，否则旧方案载入报"字段缺失"
⑤ 相关界面：configure_devices 的排除列表是否要加该键
⑥ 若影响运行：Engine/Backend 里使用它，并写入 run.json（自动，因为整份 config 都会写）
```

### 3.3 新增一列 CSV

| 目标 | 改哪里 |
|---|---|
| 所有行都要 | `Engine.base_fields` |
| 只在逐点电极表的 `routeN_` 里 | `Engine.route_detail_fields` |
| PXI 电压列 | `model.pxi_voltage_columns()`（同时影响事件、显示、恢复工具） |

改完要同步：

- `Engine.record()` 里给 `row[...]` 赋值（否则写出来是空）；
- `run.json.voltage_columns` 元数据（电压列需要）；
- `audit/recover_points.py` 的字段列表（否则恢复表缺列）；
- 测试里对列数的断言（51 / 63 / 28 这些数字会被断言）。

### 3.4 改 JSON 结构（schema 升级）

1. `VERSION` +1；
2. 在 `upgrade_document()` 末尾加 `if d['schema_version']==N:` 段，做**最小必要**迁移；
3. 无法自动转换的情况**必须显式拒绝**并给出可操作提示（参考 SR830/DC/气压扫描的拒绝写法）；
4. 追加 `migration_notes` 说明给用户弹窗；
5. 更新 `docs/05` 的迁移链表 + 测试（旧方案载入、拒绝路径、往返保存）。

## 4. 调试技巧

| 场景 | 做法 |
|---|---|
| 不想开 GUI | `python run_simulation.py 方案.json`；输出 `Points:` 与退出码 |
| 看某步为什么卡住 | 看 `events.jsonl` 的 `io_wait` / `environment_wait` / `field_wait` |
| 复现一个 bug | 用 `SimBackend` + 直接构造 `Engine`，在测试里断言事件序列（现有测试全是这个套路） |
| 检查字段集是否破坏兼容 | 载入 `examples/*.json` + `sample_output/run.json`（后者**应当**失败，它是运行记录不是方案） |
| 检查列数 | `Get-Content data.csv -TotalCount 1` 数 `,` |
| 只跑一个测试 | `python -m unittest tests.test_engine -v` |
| 抓 UI 异常 | 日志面板最多 1000 行；完整日志在 `run_dir/events.jsonl` 的 `log` 事件里 |

## 6. 交付前自检清单

```
□ $env:PYTHONUTF8='1'; python -m unittest discover -s tests   → 200 OK
□ python run_simulation.py examples/01_T_B_electrodes.json     → 30 点，退出码 0
□ python run_simulation.py examples/02_angle_1deg_MR_PXI.json  → 9 点，退出码 0
□ 旧方案（schema 7）能打开；被删除功能的方案被明确拒绝
□ data.csv 列数：PXI 51 / 逐点表(2 组) 63 / 直接接线 28
□ 版本号三处一致：gui 标题、studio.__version__、run.json.software
□ 新写的文档链接都能打开（相对路径！）
□ 没有把 legacy/ 的算法文件改动混进提交（compare_sources.py 可校验）
```

## 7. 不要做

- ❌ 为了让"测试全绿"而放宽 `validate()`（校验是安全边界）。
- ❌ 把 NULL 改成 0，或把空白环境填成上次的值。
- ❌ 在超时后自动重发 `RTOS` / `rotate_to_degree`（会造成二次运动或反转）。
- ❌ 用软件状态缓存替代 `:OUTP?` 硬件确认。
- ❌ 让 PXI 与矩阵同时启用（已在校验层拒绝，不要绕过）。
- ❌ 把 `points` 当宽表行数用（它是采集次数）。
