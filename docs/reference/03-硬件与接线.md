# 03 · 硬件与接线

> **本文是说明性参考，不是规范。** 规范效力与唯一权威以 [开发规范](../开发规范.md) 为准；本文与规范冲突时，以规范为准并应在规范 §12 登记冲突。

> 本页是**接线与地址的单一参考**。所有地址都是本机现值，现场必须按实际填写；程序不会"猜"地址。

## 1. 总体拓扑

```
                        ┌──────────────── 192.168.1.10:7020  iTC-VTI   (DB6.T1 VTI 温度 / DB3.P1 气压)
  PC ── Ethernet ───────┼──────────────── 192.168.1.11:7020  iTC-Probe (DB8.T1 样品温度 + 控温环)
                        └──────────────── 192.168.1.12:7020  iPS       (GRPZ 磁体组)

  PC ── GPIB ──► 6221 电流源 ──(RS232 null-modem + 8501 Trigger Link)──► 2182A 纳伏表   [Delta 模式]
  PC ── GPIB ──► 6221 ──(SMB: line1 → PFI0)──┐
                                             └──► PXI-4462 AI0–AI3 (SMB/BNC)            [PXI 模式]
  PC ── GPIB ──► Multi-field M6x24 矩阵 (6 行 × 24 列)
  PC ── COM ───► 旋转杆控制器
```

## 2. Oxford TeslatronPT（三台 Mercury 控制器）

| 项 | 值 |
|---|---|
| 通信 | 裸 TCP，端口 **7020**，LF 结尾；不走 VISA |
| iTC-VTI | `192.168.1.10`：`DB6.T1` = VTI 温度，`DB3.P1` = 交换气压力 |
| iTC-Probe | `192.168.1.11`：`DB8.T1` = 样品温度，并作为控温回路 |
| iPS | `192.168.1.12`：`GRPZ` = 磁体组 |
| 超时 | `io_timeout_s`，默认 5.0 s |

### 2.1 温度：目标永远是 Probe

程序里填的"目标温度"指**样品/Probe 温度**，VTI 按固定偏移跟随：

| 目标温度 | VTI 设定 |
|---|---|
| < 10 K | `T − 0.2 K` |
| ≥ 10 K | `T − 1.0 K` |

偏移只看**目标**，不看实测（1.6.x 修正项）。温度判稳**只看 Probe 实测**：`|实测 − 目标| ≤ tolerance` 且连续 `stable_s` 秒；VTI 不参与判稳。

**联动开关**：左侧"联动 VTI 控温（关闭：仅 Probe）"，只写 Probe 时 VTI 保留原设定；开关本身不发温控命令，下一次温度命令才生效，运行中（含暂停）不可切换。

### 2.2 自动气压：按实测温度的滞回

- 由左侧"自动气压设置…"唯一入口配置，全局生效（手动温控、序列温控、无温度步骤时的后台都一样）。
- 判据是**实测** Probe 温度：< 9.5 K 用低温侧压力，> 10.5 K 用高温侧压力，9.5–10.5 K 之间**保持原状态**（避免在 10 K 附近反复切换）。
- 新建方案默认 **3 mbar / 10 mbar**；1.6.x 之前的老方案迁移后保留 **4 / 10 mbar**。
- 手动设定气压前必须先关自动气压，否则被后台覆盖（`validate` 会拒绝手动气压步骤）。

### 2.3 磁场（iPS）

命令：`RFST` 设速率、`FSET` 设目标、`RTOS` 励磁、`HOLD` 保持、`RTOZ` 回零、`CLMP` 钳位、`PAUS` 暂停。

程序内的两套"容差"不要混淆：

| 容差 | 值 | 作用 |
|---|---|---|
| FSET 回读容差 | 1e-4 T | 只判断"设定值是否写进去" |
| no-op 判据 | `max(0.012 T, 步骤容差)` | 判断"电源是否需要真的励磁"；12 mT 来自 iPS 出厂 `current_epsilon=0.1 A ÷ 8.4237 A/T` |
| 步骤容差 `tolerance` | 默认 0.01 T | 判稳：`abs(实测 − 目标) ≤ tolerance` 且 `ACTN ∈ {HOLD, CLMP}` |

`set_field_verified()` 的最多 3 次尝试、60 s 间隔、等待前面板恢复等细节在 [06-执行引擎](06-执行引擎.md)。

### 2.4 角度（旋转杆）

| 项 | 值 |
|---|---|
| 串口 | `rotator_port`，默认 `COM3`；115200 / 8 / N / 1，无流控 |
| 查询 | `[?]\r\n` → `[w,D,NNNNNN]`（12 字节主体） |
| 运动 | `[r,D,SSSS,NNNNNN]\r\n`，`S/N` = round(值 × 150.13878) |
| 归零 | `[z,1,1501]\r\n`（会实际运动） |
| 停止 | **协议无停止指令** |

要点：控制器只有寄存器计数，无绝对编码器；`[?]` 回读是寄存器而非真实角度。旋转期间**不查询**，按预计时间静默等待后只回读一次；失败或超差转"等待人工确认静止后复核"。详见 [06-执行引擎](06-执行引擎.md)。

## 3. Keithley 6221 + 2182A（Delta 模式）

| 项 | 值 |
|---|---|
| 6221 地址 | `GPIB0::14::INSTR` |
| 2182A | **不直连 GPIB**：6221 与 2182A 之间接 RS232 交叉线（null-modem）+ 8501 整根 Trigger Link；Delta 触发完全由 6221 管理 |
| 程序行为 | 不设置 `:TRIG:SOUR`、不手动选线；`run_delta_once()` 走 `setup_delta → arm_delta → start_delta` |
| 测量单位 | 显式 `UNIT V`；读数即 Delta 电压 |
| 2182A 设置 | NPLC（默认 5，可 0.01–50）、固定电压量程（默认 0.1 V）、经 6221 `SERIAL:SEND` 下发 |

**连接时日志出现"6221"不代表选到了 4462**：2182A Delta 本来就要经 6221 下发命令，真正的链路在开始采集时才校验。

### 3.1 2182A 串口链路预检（开跑前人工执行一次）

2026-11-06 的事故教训：WCG 序列在**第一个 Delta 点**就失败（`Keithley6221Error: 2182A configuration: ''`），而当时已经烧了约 20 h 降温。

根因是 6221↔2182A 的 RS-232 串口往返延迟在真机上可达 ~4 s，间歇性超时；当时的驱动版本还额外做了"每点 3 次串口往返校验"，把这种抖动放大成必然失败。

现在驱动已**整体回退到 1017 版流程**（每点只做单向写 NPLC/RANG，不做串口往返校验）。

**程序不会在启动时自动做这项检查**——这是刻意的（2026-11-07 决定：Delta 照搬 1017 版，不加任何额外变化；且预检本身也是一次串口往返）。所以由操作者在开跑前手动执行一次：

```powershell
# 只读预检，不改任何仪器设置。默认 GPIB0::14::INSTR
python check_2182_link.py                   # 或 check_2182_link.py GPIB0::16::INSTR
```

判读（脚本自述，退出码非 0 表示不该开跑）：

| 现象 | 结论 | 处置 |
|---|---|---|
| 全部查询 < 2 s 且 `NVPR=1` | 链路正常 | 可以开跑 |
| 有响应但延迟 4–10 s | 链路劣化 | 查线 / 重启 2182A 后复测，恢复 < 2 s 再跑长序列 |
| `NVPR=0` 或完全无响应 | 链路死 | 查 RS-232 两端、2182A 面板 `SHIFT+RS-232`（ON / 19200 / XON/XOFF / CR）、重启 2182A |

> WCG 20261106 的 410 报错（"Model 2182A required"）与本条同源：老驱动在 `:SOUR:DELT:ARM` 才检测到 2182A 不在线。

## 4. NI PXI-4462（PXI 模式）

| 项 | 值 |
|---|---|
| 触发 | 6221 **line 1** → **PFI0**（SMB），**下降沿**；程序固定，界面不提供选择 |
| 源波形 | SIN，offset = 0，`phase_marker=True`，`marker_position` 默认 90° |
| 采集 | 4 路 AI 同任务同步采样，差分（DIFF）；耦合**默认 DC，可选 AC**（−3 dB @ 3.4 Hz，只去直流背景，不去 f 上的串扰）；IEPE 关闭 |
| 通道 | 固定 ai0–ai3（旧方案的子集会被强制补全） |
| 采样 | 默认 51.2 kHz × 1 s，整数周期对齐；限 8–2,000,000 点、≤ 600 s |
| 量程 | 六档，四路统一：±0.316 / 1 / 3.16 / 10 / 31.6 / 42.4 Vpk |
| 激励 | 6221 交流输出，整段序列**持续 ON**（温度/磁场/角度变化期间也保持）；**电流可按步骤不同**，变化时在步骤边界关源重配后重开 |

⚠️ 三条容易踩的：

1. **必须关闭矩阵**。持续交流输出不允许切继电器，`validate_config` 直接拒绝"PXI + 矩阵"。
2. **同一段序列的 PXI 步骤必须参数一致**（电流、频率、相位、谐波、DAQ 设置），否则 `pxi_run_params` 报错要求分开运行。
3. **±42.4 V 档不支持硬件过载检测**，程序会标 `hardware_overload_supported=false`，不等于"确认无过载"。

## 5. Multi-field M6x24 矩阵（四端切换）

| 项 | 值 |
|---|---|
| 资源 | `matrix_resource`，默认 `GPIB0::20::INSTR`；**只支持 GPIB** 地址（0–30） |
| 拓扑 | 6 行（A–F，仪表侧）× 24 列（样品侧 pin 1–24） |
| 帧格式 | `[nnnnnnnn,nnnnnnnn,nnnnnnnn]\r\n`；每段 8 位，数字 0–6 = 该列接哪一行，0 = 断开；段 1/2/3 对应列 1–8 / 9–16 / 17–24 |
| 命令语义 | **整帧绝对状态**，每次下发完整 24 列；设备**无继电器状态回读** |
| 四端映射 | `matrix_rows` 四个不同接口 = `[I+, I−, V+, V−]`，默认 `[1,2,3,4]` = A/B/C/D |
| 一口多 pin | `columns` 每项可为 pin 或 pin 列表，例如 `[[12,11],9,[8,7],6]`；同口并联，电流是整个口的总电流 |
| 唯一性 | 每个 pin 只能属于一个口 |

**切换时序**（由引擎保证，`route()`）：

```
确认关源（:OUTP? 三次核验） → 等待 matrix_off_delay_s（默认 0.5 s）
  → 全断开 + 设置新映射 → 等待 matrix_settle_s（默认 0.5 s） → 允许通电
```

关源未确认就**禁止切换**（`HardwareBackend.off()` 会抛错）。

典型的 A–F 用法：A=I+、B=I−、C=V+、D=V−，E/F 备用。

## 6. 设备启用与互锁矩阵

| 配置组合 | 结果 |
|---|---|
| `enable_matrix=True` 且 `enable_source=False` | 拒绝（矩阵必须配 6221） |
| `measurement_device='pxi'` 且 `enable_matrix=True` | 拒绝（持续输出不能切换） |
| 启用矩阵 + 逐点电极表 + 显式 `route`/`channels` 节点 | 拒绝（路由会被覆盖；禁用节点不算冲突） |
| 旋转杆未启用但序列里有角度步骤 | 硬件模式下拒绝 |
| 两个 VISA 地址相同且都启用 | 拒绝 |
| 手动气压步骤 + 自动气压开启 | 拒绝 |

## 8. 现场必须自己核对的事

1. 矩阵 `matrix_rows` 与实际丝印 A–F 的对应关系（程序不会改接线）。
2. 旋转杆方向位 `D` 的物理约定（曾两次改动，最终以现场蜂鸣+目视标定为准）。
3. 4462 四个 BNC 接的是哪一路电压（每根 BNC 中心为正、外壳为负，不是相邻 BNC 组成差分对）。
4. 2182A RS232 是否为交叉线、Trigger Link 是否为整根 8501。
5. 旋转杆机械零位（`[z,1,1501]` 会真的转，程序不会自动调用）。
