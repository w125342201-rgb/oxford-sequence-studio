# 06 · 执行引擎

> **本文是说明性参考，不是规范。** 规范效力与唯一权威以 [开发规范](../开发规范.md) 为准；本文与规范冲突时，以规范为准并应在规范 §12 登记冲突。

`studio/engine.py` 的 `Engine` 是唯一碰仪器的地方。本页说明"一次运行到底发生了什么"，以及四条最难理解的行为：**环境无限等待**、**NULL 规则**、**暂停/停止**、**PXI 逐步骤电流重配**。

---

## 1. 运行生命周期（`Engine.run`）

```
1. deepcopy(nodes) → normalize_pxi_channels()
2. validate(nodes, config, hardware=not simulated)      ← 契约校验
3. validate_device_selection(nodes, config)             ← 设备一致性
4. 已连接设备 == config.measurement_device ?           ← 否则报错要求重连
5. continuous_pxi = pxi_run_params(nodes)              ← PXI 整段参数（或 None）
6. 重置计数器 / 环境缓存 / 接受队列
7. run_dir = <输出目录>/YYYYmmdd_HHMMSS_<hex8>/        ← 必须不存在
8. 写 run.json（status="running"），含 planned_workload、完整 config 与 nodes
9. 计算 CSV 列：base_fields + voltage_fields + routeN_ 详情列
10. 写 run.json 的 voltage_columns / counter_semantics 元数据
11. 打开 events.jsonl 与 data.csv（编码 utf-8-sig）
12. PXI：backend.begin() 立刻开 6221 交流波形（整段保持 ON）
13. execute(nodes)
14. finally: backend.off()；若 status != completed 再 hold()
15. finally: 重写 run.json（tmp → replace），emit 最终状态
```

失败分类写在 `run.json.status`：

| status | 含义 |
|---|---|
| `completed` | 全部步骤正常结束（可能含 NULL 点） |
| `stopped` | 用户停止（`Stopped`） |
| `failed` | 抛出非停止异常，`error` + `traceback` 已保存 |
| `cleanup_failed` | 正文结束但关源/清理也失败——**必须现场检查仪器** |

> 即便运行失败，`off()` 也一定会被调用一次。`off()` 若失败，`run.json` 会记录 `cleanup_errors`。

## 2. `execute()` 与路径

`path` 是排查一切问题的索引：

```
/1:sweep[temperature=4.0]/1:sweep[field=0.05]/1:resistance
```

- 数字是**同层序号（从 1 开始）**，只计顶层兄弟位置，不含禁用项过滤。
- 容器展开后缀：`[i+1]`（repeat）、`[轴=值]`（sweep）、`[名称:电极]`（channels）、`[direct]`（矩阵关闭时的 channels）。
- 每个节点进入写 `node_start`，离开写 `node_done`；中间异常则没有 `node_done`。

节点分派：

| kind | 动作 |
|---|---|
| `temperature`/`field`/`pressure`/`angle` | `environment(kind, target, params)` |
| `wait` | `wait(seconds)`（可被暂停打断并顺延） |
| `route` | `route(params)` |
| `repeat` | 循环 `count` 次执行 children |
| `sweep` | 逐目标 `environment()` 后执行 children |
| `channels` | 矩阵关闭时只按"直接接线"执行一次 children；开启时逐路由 `route()` + children |
| `resistance` | `measurement(n)` |

## 3. 环境等待：无限等待 + 连续稳定

`_environment(axis, target, params, context)`：

1. **先关源**（PXI 连续模式例外，整段保持输出）。
2. 设置命令：
   - **磁场 / 角度**直接调用 `set_environment()`，**不走无限重试**——因为响应丢失不代表命令没执行，重发可能造成二次运动。
   - 温度 / 气压走 `retry_io()`（超时才重试）。
   - 若抛的是"环境类 IO 异常"（超时 / Mercury 通信异常），只记日志并转入观测等待，不重发运动命令。
3. 进入循环（每 0.5 s 一次，模拟模式 0.05 s）：

```
gate()                                  ← 暂停闸门
接受人工请求?
poll()                                   ← 每 ≥1 s 真读一次环境（模拟模式每次都读）
|实际 − 目标| ≤ tolerance ?
  ├─ 角度还需 rotation_target is None
  ├─ 磁场还需 ACTN ∈ {HOLD, CLMP}
  └─ 满足后开始计"连续稳定"，满 stable_s 才返回
不满足 → stable 计时清零
磁场：超 timeout_s 只更新提示（每 60 s 一次），继续等
其他轴：超 timeout_s 只记一条日志，继续等
每轮 emit('progress', 残差/已等时间/近 60 s 变化)
```

关键点：

- **环境步骤没有总等待时限**。`timeout_s` 只用来"提醒"，不终止序列。
- 离开容差、暂停、通信失败、复位都会**重新计时**，不把之前的等待拼成连续稳定。
- 磁场到位但电源还在 `RTOS`/`RTOZ`/`PAUS` 时**不算到位**。
- 模拟模式把稳定时间压缩到 `min(stable_s, 0.05)`，只为让测试跑得快。

### 3.1 磁场：励磁失败后等前面板

`set_field_verified()` 每阶段最多 3 次尝试、间隔 60 s；耗尽后不结束实验，而是：

- 保留当前步骤、循环位置、数据文件；
- 持续读取磁场，**不再重发** `FSET`/`RTOS`；
- 你在电源前面板处理故障即可，实际磁场进入容差且 `HOLD/CLMP` 并连续稳定后**自动继续**；
- 等待期间不采该点、不跳过节点。

`no_op_ramp`（电源认为"已经在目标"而未起励）但实测超容差时，写 `field_not_started` 事件并进入等待，**不自动放宽容差**。

> 这就是 1.7.7 强调的耦合：容差 0.01 T 大于某些细步长，细步长 MR 必须单独调小该步骤容差。

### 3.2 角度：静默等待 + 单次回读（无人工复核入口）

```
rotate_to_degree(target, rate)          ← 立即返回，不阻塞
预计时长 = |target − 当前| / rate + rotation_margin_s(1.5 s)
运动期间禁止任何角度查询
计时到 → service() 里自动回读一次
  ├─ 在容差内 → 清 rotation_target，正常继续
  └─ 超差/失败 → 记 rotation_error，停止自动查询，环境步骤保持等待
```

超差/失败后的唯一出路：**没有 GUI 恢复入口**（自 2026-11-11 起，规范 D-023/W-008 删除了"确认静止后复核"与"停止后解除目标"两个按钮）。环境步骤会保持等待、不采集、不切电极（`ensure_rotation_idle` 仍拦截），日志与界面提示"停止后检查旋转杆"；只能点"停止运行"退出。

### 3.3 Delta 采集流程（1017 版，**不做每点串口校验**）

`run_delta_once()` 的实际顺序：

```
clear_errors()                     清 6221 错误队列（旧错误会污染后续 Trace 读取）
setup_delta()                      串口**只单向写** NPLC / 固定量程
arm_delta() → start_delta()        :SOUR:DELT:ARM → :INIT
等 STAT:OPER:EVEN? bit 1           完成标志（不用 :TRAC:POIN:ACT?，该固件会挂）
TRAC:DATA?                         为空或失败则 :SENS:DATA? 兜底
disarm_delta() → 解析              返回值必须是 1 个点
```

**为什么每点没有串口往返校验**：2026-11-07 的整体回退（详见 [11-版本历史 §5](11-版本历史.md)）。真机上 `NPLC?`/`RANG?`/`:SYST:ERR?` 往返可达 ~4 s，逐点校验会把链路抖动放大成必然失败（2026-11-06 序列 三次运行全部死在第一个 Delta 点）。回退后**程序不做任何自动链路检查**；需要时由操作者在开跑前手动跑 `check_2182_link.py`（[03-硬件与接线 §3.1](03-硬件与接线.md)）。

超时行为：`timeout_s` 内未见完成位 → 先 `ABOR` + `disarm` 再抛 `TimeoutError` → 该点 `NULL` 并继续。**不会**把 6221 留在 ARM 状态带着输出。`timeout_s` 也用于每点整体上限，所以它是"单次 Delta 采集超时"，不是环境等待阈值。

### 3.4 PXI 步骤边界重配（逐步骤电流，D-024）

PXI 运行开始时按**第一个**采集步骤的参数 `begin()` 一次，并记入 `pxi_applied`。之后每进入一个 PXI 采集步骤，都比较该步骤参数与 `pxi_applied`：

```
_current_a 不同（实际只会是它）→ begin()：关源确认 → 改幅值 → verify_ac → arm/init
                                → 更新 pxi_applied → 写 pxi_reconfigure 事件
其余参数不同 → 不会发生（校验层已拒绝）
```

- 暂停后恢复用 `pxi_applied`（最近一次真正下发的参数），不会退回序列开头的电流。
- 频率/相位/谐波/marker/DAQ 仍然全程固定（由 `pxi_run_params` 强制），因此 CSV 列集合不变。
- 切换代价：约 1–3 s 无激励（含 3 次关源确认与回读校验），由该步骤自己的 `settle_s` 缓冲。

## 4. NULL 规则：哪些继续、哪些停整轮

| 情况 | 处理 |
|---|---|
| Delta 超时 / 读数非数值 / 点数 ≠ 1 / 超量程 | 该点 `NULL`，**继续**下一电极/点 |
| 4462 硬件过载 / 过载状态读不到 / 无效数值 / 形状不符 / 采集超时 | 该点 24 列 `NULL`，**继续** |
| 同一次采集连续无效 ≥ 10 次 | 红色提示 + 每 10 次写 `invalid_streak` 事件，**仍继续** |
| 环境回读无效（当前运行控制过的轴、自动气压的 Probe/压力、联动时的 VTI） | **无限重试**，阻塞新采集，但不算失败 |
| 环境回读中非关键通道缺失 | 记 `partial`，继续 |
| **源顺从 / 过温 / 源状态错误 / 关键设置回读三次不符** | **整轮失败** + 清理 |
| **关源无法确认（`:OUTP?` 三次）** | **失败**，且禁止后续矩阵切换 |
| 配置非法、文件写入失败、矩阵命令失败 | **整轮失败** |
| 用户停止 | `stopped`，保留已完成数据 |

记录无效点时：先确认关源（非 PXI），再写 `invalid_raw` 事件（含 `route`、`columns`、`logical_point`、`route_index`、异常原因、`repr(raw)`），最后生成全 `None` 的结果行。**下一次采集不会被永久禁用**，同一环境点下会照常再试。

## 5. 暂停 / 停止 / 恢复

| 操作 | 实现 | 边界 |
|---|---|---|
| 暂停 | `Engine.pause` 置位；`gate()` 在**下一个节点/采集边界**生效：关源 → `state=paused` → 写 `pause` 事件 → 空转（不读环境）→ 复位后重开测量 | 采集中不打断当前点；环境等待中会立即关源 |
| 继续 | 清 `pause`；`gate()` 里 `begin()` 重建测量准备（PXI 重开波形），写 `resume` 事件 | 暂停期间不读环境，控制器失联不会卡住继续/停止 |
| 停止 | `Engine.stop` 置位；`check()` 抛 `Stopped`；`finally` 关源 + `hold()` | **不是硬件急停**；旋转杆协议无停止命令，已发出的运动无法撤回 |

`retry_io()` 的重试循环里也检查 `stop`，所以"通信一直超时"时停止仍然有效。

## 6. 人工接受当前环境值（已移除）

该功能曾用于"环境到不了目标，但我确认现在这个值可以接受"。**2026-11-11 起已整体删除**（规范 D-023 / W-008）：按钮、`wait_context`、`environment_accept` 队列、`_accept_environment_request`、`accept_stationary_angle` 均不存在。

保留的痕迹（仅为数据兼容，不再产生新值）：

| 项 | 现状 |
|---|---|
| `environment_overrides` CSV 列 | 保留，恒为 `{}`（列数不变） |
| `environment_status` 的 `accepted_by_operator` / `partial_accepted_by_operator` | 保留作历史值，不再写入 |
| 事件 `environment_accepted` | 停用，名称不得复用 |

现在的行为：环境未达标或未满足连续稳定 → **继续等待**，没有跳过门槛的入口。

## 7. 逐点电极表（矩阵）

`enable_matrix=True` + `matrix_each_point=True` 时，`measurement()` 的执行顺序是：

```python
for sample in range(samples):
    logical_point += 1
    for ri, route in enumerate(point_routes, 1):
        route_index = ri
        gate()                     # 暂停点
        route(route)               # 关源 → 等待 → 切换 → 等待
        begin()                    # 准备测量
        data = acquire_delta()     # 无效 → NULL
        record(data)               # 同一逻辑行，写入第 ri 个电压列
        finally: off()             # 关源（停止时不重试）
```

- 两种模式（`channels` 显式循环 / 逐点遍历）**互斥**，同时存在会在 `validate` 阶段被拒。
- 矩阵关闭时 `channels` 节点只执行一次，标记"直接接线"。
- 每个电极组合的实际环境与状态写在 `routeN_*` 列；公共环境列属于**第一组**电极。

## 8. 采集与落盘顺序（`record()`）

这个顺序是刻意的，**不要调换**：

```
① finite_tree(data)                     非有限值 → invalid_raw 事件 → 抛错
② event('acquisition', ...)              ← 先落盘！此时还没读环境
③ 环境回读（stop 时跳过，标 stopped）
④ points += 1；组装行（含 measurement_mode/environment_status/...）
⑤ event('point', row)                    ← 完整行进事件日志
⑥ record_table(row)                      ← 宽表 seek/truncate/flush/fsync
⑦ emit('point', row)                     ← 最后才给 UI
```

所以：**只要看到 `acquisition` 事件，这次电压就不会因为环境通信失败而丢**。恢复工具 `audit/recover_points.py` 正是靠这一点重建长表。

`record_table()` 的写法：先 `seek` 到本逻辑行的起始位置，`writerow` 后 `truncate` + `flush` + `fsync`——每测完一个电极就整体重写该行，保证中断时"已测列有值、未测列留空"。

## 9. 计数语义

| 字段 | 含义 |
|---|---|
| `points` | 采集次数；**只是 `acquisition_count` 的兼容别名** |
| `acquisition_index` | 事件里第几次采集（1 起） |
| `logical_point` | 一个采样点在全部电极组合中的编号（宽表 `point` 就是它） |
| `route_index` | 该逻辑点内的电极序号（逐点表时 1..N） |
| `csv_rows` | **首次**完整落盘成功的逻辑行数（可能含尚未测完电极的末行） |

`run.json` 的 `counter_semantics` 会把这套语义写进文件，避免以后分析脚本猜。

## 10. 清理

```
finally:
    backend.off()                 # 波形中止 / sweep 中止 / 输出关 / 置零 / :OUTP? 三查
    if status != 'completed':
        backend.hold()            # 磁场 HOLD
    任何清理异常 → cleanup_errors / cleanup_tracebacks，status 降级为 cleanup_failed
```

关闭窗口（正常退出）会额外在确认关源后等待 `matrix_off_delay_s` 再断开全部继电器，然后关闭连接。**任务管理器强杀 / 掉电无法靠代码保证关源**，必须到仪器端确认 OFF。
