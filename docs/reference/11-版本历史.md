## 2. 几条"改了又改"的线（看历史时容易误解）

### 2.1 Delta 除数

```
1.6.0  保留原程序的 /2（delta_divisor 持久化）
1.6.3  移除额外 /2，固定 R = V/I；旧方案导入时归一为 1
```
所以 **1.6.3 之前的 Delta 电阻可能小一半**；电压值本身从未被改写。

### 2.2 磁场容差与 no-op 判据

```
早期   容差 0.0002 T
1.7.5  标定 no_op 判据 = max(0.012 T, 容差)，并区分"电源没起励"与"已到位"
1.7.7  默认容差改为 0.01 T（⚠ 与 12 mT 的交叠见下）
```
`0.012 T` 来自 iPS 出厂 `current_epsilon = 0.1 A ÷ 8.4237 A/T`。1.7.7 把默认容差提到 0.01 T 后，**细步长（≤10 mT）必须单独调小该步骤容差**。

### 2.3 4462 谐波与相位

```
1.6.5  固定 4 通道，只导出 1f/2f 幅值（8 列）
1.6.6  改为 24 列（幅值/X/Y），引入 marker/phase 显式字段
1.6.7  修短窗泄漏与频点取整
1.6.9  默认 marker=90°、1f=0°、2f=−90°
1.7.0  增加 3f 选项（默认 −180°），3f 模式把 2f 当干扰项拟合
```
旧方案缺 `marker`/`phase2` 时补 **0°**（历史行为），新建节点才是 90°。这个"默认值不同"是刻意的。

### 2.4 设备选择

```
1.6.2  设备只在左上角选
1.7.1  真实运行校验会拒绝不一致，但模拟仍按旧步骤跑 ← 缺陷
1.7.2  选择即同步全部采集步骤；连接锁定身份；后端 begin/measure 再校验
```

### 2.5 数据列

```
1.6.x   8 列 → 24 列（4462）
1.7.3   + 状态与时间列
1.7.4   4462 标准表 48 列；逐电极表每组 +14 列
1.7.5   4462 标准表 50 列（+acquisition_index、angle_read_time_unix）
1.7.6   4462 标准表 51 列（+environment_overrides）
```
**永远按列名读，不要按列号。**

## 3. 当前版本（1.7.9）需要特别记住的三件事

1. 默认是"常规步长（≥50 mT）磁场扫描 + 0.1 A 固定激励"，**不为细步长 MR 优化**。
2. Compliance 105 V 是**限压不是限功率**，开路/高阻时 10.5 W 全落在样品与引线上，应按 `I×R×2` 设。
3. 量程刻意未跟着改：2182A 0.1 V 档 ↔ R ≤ 1 Ω；4462 ±316 mV 档 ↔ R ≤ 3.16 Ω。超出就改档，否则整点 NULL。

## 5. 1.7.7 发布后的现场修正（2026-11-07，未改版本号）

版本号保持 1.7.7，但 `legacy/` 的 Delta 驱动被**整体回退**到 1017 版流程。

| 项 | 内容 |
|---|---|
| 症状 | 2026-11-06 序列 三次运行全部在**第一个 Delta 点**（10 K / 9 T / route A）失败，0 行数据；报 `Keithley6221Error: 2182A configuration: ''` |
| 直接原因 | `query_2182(':SYST:ERR?')` 4 s 超时返回空串；NPLC?/RANG? 靠重试勉强通过 → 6221↔2182A 串口链路延迟逼近窗口 |
| 深层原因 | 10-19 之后加入的 `verify_delta_settings` 让**每点**发生 3 次串口往返；老代码（10-17~10-27 跑过 9090/3400/1530 点）只有单向写 + 6221 内部 ARM |
| 处置 | `run_delta_once` 逐字节恢复 261031buckup 原文（唯一机械改动 `time.sleep` → `self._wait`，保留停止响应）；删除 `verify_delta_settings` / `reuse_2182_settings` / `_delta_2182_cache` 包装；`studio/backend.py` 的 `measure` 去掉 `reuse_2182_settings=True` |
| 影响 | 1.7.5 的"Delta 配置复用"（P2-6）随之撤销；测试从 201 项变为 200 项（`test_audit_175` 改为断言"不做串口往返"，`test_reliability_173` 重写 2 个、删除 1 个回读校验测试） |
| 新增工具 | `check_2182_link.py`（只读链路预检，**人工执行**，程序内不做自动检查；见 [03 §3.1](03-硬件与接线.md)） |
| 现存风险 | 链路劣化不会在前 20 h 暴露，只会在第一个 Delta 点失败 → 开跑前由操作者手动预检 |

版本考古（重要：不要从错的拷贝运行）：

| 拷贝 | 内容 | Delta 行为 |
|---|---|---|
| `261031buckup`（快照 ~10-19，1.7.2） | 无 `verify_delta_settings` | 单向写 + ARM，**已实机跑通 9090 点** |
| `261101buckup`（1.7.6） | 带逐点串口校验 | 会在 该场景复现失败 |
| 当前工作区（1.7.7 + 11-07 回退） | 与 261031 相同的 Delta 流程 | 现场重跑前请先 `check_2182_link.py` |
