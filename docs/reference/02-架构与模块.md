# 02 · 架构与模块

> **本文是说明性参考，不是规范。** 规范效力与唯一权威以 [开发规范](../开发规范.md) 为准；本文与规范冲突时，以规范为准并应在规范 §12 登记冲突。

## 1. 四层结构

```
┌──────────────────────────────────────────────────────────────┐
│  studio/gui.py        Tk 界面（单线程：只碰控件，不碰仪器）    │
│    · 序列树编辑 / 参数表单 / 曲线 / 日志                       │
└───────────────▲──────────────────────────┬───────────────────┘
                │ events 队列 (emit)       │ jobs 队列 (submit)
┌───────────────┴──────────────────────────▼───────────────────┐
│  studio/engine.py     执行引擎（由唯一 worker 线程调用）       │
│    · 嵌套执行 / 环境等待 / 落盘 / 暂停停止 / NULL 规则         │
└───────────────▲──────────────────────────┬───────────────────┘
                │ 统一后端接口              │
┌───────────────┴──────────────────────────▼───────────────────┐
│  studio/backend.py    设备适配层                              │
│    · SimBackend（纯 Python 物理近似）                          │
│    · HardwareBackend（懒加载 legacy 驱动，单点持有）           │
└───────────────▲──────────────────────────┬───────────────────┘
                │                          │
┌───────────────┴──────────────────────────▼───────────────────┐
│  legacy/*            原样保留的驱动（不改算法）                │
│    oxford/ keithely6221_2182A/ pxi4462/ matrix/ rotater/      │
└──────────────────────────────────────────────────────────────┘
         ▲
         │ 契约
┌────────┴─────────────────────────────────────────────────────┐
│  studio/model.py    序列模型：常量 / CONFIG / SPECS / 校验 /   │
│                     迁移 / 工作量 / 设备选择                   │
└──────────────────────────────────────────────────────────────┘
```

依赖方向是**单向**的：`model` 不 import `backend`，`engine` 不 import `pyvisa`/`nidaqmx`，`gui` 不直接操作仪器。`legacy` 驱动也不 import `studio`（唯一的例外是 `model.validate` 里 import `legacy.pxi4462.capture_limits` 做采样长度校验，以及 `engine` import `normalize_action`）。

## 2. 各模块职责

### `studio/model.py`（483 行）— 唯一的"契约"

| 内容 | 说明 |
|---|---|
| 硬件常量 | `FIELD_MAX_RATE_T_PER_MIN=0.237`、`SOURCE_MAX_CURRENT_A=0.105`、`SOURCE_MAX_COMPLIANCE_V=105`、`DEFAULT_SOURCE_CURRENT_A=0.1`、`DEFAULT_FIELD_TOLERANCE_T=0.01` |
| `CONFIG`（34 字段） | 设备地址、启用开关、实验限值、矩阵延时、气压策略、测量设备。`validate_config` 要求键集**完全相等** |
| `SPECS`（10 种节点） | 每种节点的中文标签 + 默认参数；`node()` 用它生成新节点 |
| `LABELS` | 参数中文名（全是契约的一部分，测试会校验） |
| `span()` | Decimal 精确点列，按轴精度（温度 0.1 K / 磁场 0.001 T / 角度 0.1°）拒绝不合精度输入 |
| `pin_groups()` / `columns()` | 四端口电极映射校验（1–24 pin，不可重复） |
| `validate()` | 唯一的执行前检查（结构 + 数值 + 交叉条件 + 工作量上限） |
| `workload()` | 统计 `operations` / `acquisitions` / `csv_rows`（不等于 SCPI 命令数） |
| `upgrade_document()` | schema 1→7 迁移链，**拒绝**无法自动转换的旧方案 |
| `set_measurement_device()` | 显式 UI 选择时同步所有采集步骤（含禁用、嵌套） |

### `studio/engine.py`（603 行）— 执行

- `Engine.run()`：校验 → 建运行目录 → 写 manifest → 开 `events.jsonl`/`data.csv` → `execute()` → 清理（off + hold）→ 收尾写 manifest。
- `execute()` 递归解释节点树；`path` 形如 `/1:sweep[field=0.05]/1:resistance`，是排查的主键。
- `_environment()`：无限等待 + 连续稳定 + 磁场状态机（2026-11-11 起**无**人工接受/角度复核入口，见规范 D-023）。
- `retry_io()`：**只重试超时/通信异常**（`is_timeout`、Mercury 通信异常、可选的无效读数），永不重发运动命令。
- `record()` / `record_table()`：先写事件，再刷环境，再回填宽表（`seek` + `truncate` + `fsync`）。

### `studio/backend.py`（338 行）— 适配

同一接口两套实现，保证引擎不改一行就能在模拟与真机之间切换：

`connect / snapshot / service / set_environment / route / begin / measure / off / hold / close`（另有 `accept_stationary_angle`、`refresh_angle`、`invalidate_measurement_cache`、`reconnect_transport` 等可选项）。

- `SimBackend`：环境值直接赋值；电阻用 `R(T) ∝ 1/(1+exp((Tc−T)/0.12))` 的类超导跃变，磁场升高会压低 Tc，便于看曲线形态。
- `HardwareBackend`：`connect` 里才 import 驱动；`off()` 严格执行"波形中止 → sweep 中止 → 输出关 → 置零 → `:OUTP?` 三查"，任一失败即抛错并**禁止后续矩阵切换**。

### `studio/gui.py`（901 行）— 界面

单文件，含 `RouteEditor`（电极表编辑器）、`Form`（通用参数表单）、`App`（主窗口）。
`Form` 会根据 `visible_fields()` 隐藏当前设备用不到的参数，但**保留其存储值**（切换设备不丢参数）。

### `studio/instrument_options.py` — 离散选项

只放"标签 ↔ 存储值"的精确映射与 `wiring_hint()`。硬件档位表来自 `legacy/pxi4462/input_ranges.py`（单一来源，界面和驱动共用）。

## 3. 线程模型

| 线程 | 职责 | 绝不做什么 |
|---|---|---|
| Tk 主线程 | 控件、`drain()` 事件消费、绘图 | 不调用任何仪器方法 |
| worker（1 个，daemon） | 执行 job：connect / run / hold / angle_read / angle_release / vti_link / disconnect / quit | 不直接改控件，只 `emit()` |
| 引擎内部 | 与 worker 同线程 | — |

两个队列：

- `jobs`：GUI → worker，元素 `(kind, data)`。
- `events`：worker → GUI，`self.emit(kind, data)`。GUI 每 80–100 ms 调 `drain()`，一次最多消费 300 条。

**事件种类（GUI 侧 15 种）**：`environment`、`stale`、`state`、`progress`、`environment_waiting`、`quality`、`route`、`run_dir`、`connected`、`idle`、`node`、`point`、`log`、`error`、`quit`。

**跨线程的只有三样东西**：`Engine.stop`（Event）、`Engine.pause`（Event）、`Engine.rotation_recheck`（Event）以及 `Engine.environment_accept`（SimpleQueue）。UI 从不直接调用仪器，全部转成 job 或置位 Event 交给 worker。

## 4. 关键不变量（改代码前请确认没有破坏）

1. **单所有者**：任何时刻只有一个线程碰仪器。UI 想读角度必须 `submit('angle_read')` 或置 `rotation_recheck`。
2. **校验先行**：`Engine.run()` 第一步就是 `normalize_pxi_channels` + `validate` + `validate_device_selection`；GUI 的"校验"按钮走同一函数。
3. **字段集封闭**：节点参数字段集必须与 `SPECS` 完全一致。**新增参数必须同时改 `SPECS` 和 `upgrade_document`/`normalize_pxi_channels`**，否则所有旧方案载入失败（`validate` 会报"参数字段缺失或未知"）。
4. **先记录后通信**：`record()` 在写 `acquisition` 事件时**尚未**做环境回读，保证"电压先落盘，环境失败不丢点"。
5. **关源可验证**：`off()` 失败 → 抛错 → 本轮失败，不允许"假定已关"再切继电器。
6. **运动命令不重放**：超时只观测、不重发（磁场 `RTOS`、旋转 `rotate_to_degree`）。
7. **默认值单一来源**：默认值引用模块常量，不写第二份字面量（1.7.7 的重点）。

## 5. 一次运行的调用链（真实硬件、Delta、逐点电极表）

```
App.start()
 └ submit('run', (nodes, output))
   └ worker: Engine.run()
      ├ validate(...) / validate_device_selection(...)
      ├ pxi_run_params(nodes) → None（Delta 模式）
      ├ mkdir data/20261111_073906_b3adaa77 ; run.json
      ├ continuous_pxi？
      │    └ PXI：backend.begin() 开 6221 交流波形（整段保持 ON）
      └ execute(nodes)
         ├ sweep → _environment() 逐目标等待（每 0.5 s poll，1 s 刷新环境）
         └ resistance → measurement()
            ├ per_point: route() 关源→延时→切矩阵→延时
            ├ backend.begin() 准备测量
            ├ acquire_delta() → backend.measure()
            ├ record() → events 'acquisition' → 环境回读 → events 'point' → record_table()
            └ finally: backend.off()
      ├ backend.off() / hold()
      └ run.json 收尾（status / points / acquisition_count / csv_row_count / invalid_points）
```

## 6. 扩展点

| 想做的事 | 改哪里 |
|---|---|
| 新增一种步骤类型 | `SPECS` + `CONTAINERS`(如需) + `LABELS` + `validate()` 分支 + `Engine.execute()` 分支 + `workload()` + `visible_fields()`（如需） |
| 新增一个配置项 | `CONFIG` + `validate_config()` 校验 + `CONFIG_LABELS` + `upgrade_document()` 的 `setdefault`（**必须**，否则旧方案缺字段） |
| 支持新的环境轴 | `SPECS` 里加轴 + `clean_environment()` 的 key 列表 + `backend.set_environment()` + `environment()` 的容差/状态逻辑 |
| 换一种测量设备 | `instrument_options.OPTIONS['measurement_device']` + `selected_mode()` + `set_measurement_device()` + `pxi_run_params()`/`require_measurement_device()` + `HardwareBackend.begin/measure` |
| 加一列 CSV | `Engine.base_fields`（所有表）或 `route_detail_fields`（逐电极表）或 `pxi_voltage_columns()`（电压列）+ `run.json` 的 `voltage_columns` 元数据 + `record_table()` |

改完请按 [10-开发指南](10-开发指南.md) 的清单自检：**旧方案能否载入、旧 CSV 列名是否还在、模拟跑是否通过、全量 200 项测试是否通过**。
