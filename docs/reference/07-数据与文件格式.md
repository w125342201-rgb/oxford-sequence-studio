# 07 · 数据与文件格式

> **本文是说明性参考，不是规范。** 规范效力与唯一权威以 [开发规范](../开发规范.md) 为准；本文与规范冲突时，以规范为准并应在规范 §12 登记冲突。

## 1. 目录布局

每次运行生成一个**独立目录**，名字为 `YYYYmmdd_HHMMSS_<uuid8>`：

```
<数据目录>/
└── 20261111_073906_b3adaa77/
    ├── run.json        本次的完整配置、节点树、列元数据、最终状态
    ├── data.csv        宽表：一个采集点一行
    ├── events.jsonl    逐次原始记录：一行一个 JSON 事件（含完整 traceback）
    └── waveforms/      仅当 daq_save_waveforms=true 时存在，每点一个 .npz
```

- 目录**不允许已存在**（`exist_ok=False`），避免覆盖。
- `data.csv` 用 `utf-8-sig`（带 BOM），Excel 直接双击不乱码；`events.jsonl` 用 `utf-8`。
- 数据目录默认 `./data`，可在界面底部改。

## 2. `run.json`

| 字段 | 说明 |
|---|---|
| `schema_version` | 固定 7 |
| `software` | 例 `"Oxford Sequence Studio 1.7.9"` |
| `simulation` | 是否模拟运行 |
| `planned_workload` | 运行前的 `{operations, acquisitions, csv_rows}` |
| `config` | 本次实际使用的 34 字段配置（含 `max_current_a`、`compliance_v`） |
| `nodes` | 本次实际执行的节点树（含每个节点的参数） |
| `voltage_columns` | 电压列 → 通道/谐波/分量/单位 或 路由元数据 |
| `counter_semantics` | 各计数字段的文字定义 |
| `environment_columns_note` | 逐点电极表时说明"公共环境列属于首组电极" |
| `pxi_contract` | PXI 固定条件（频率/相位/谐波/marker/DAQ），仅 PXI 运行 |
| `pxi_per_step_current` | 本次序列是否含不同激励电流（true 时会有 `pxi_reconfigure`） |
| `status` | `completed` / `stopped` / `failed` / `cleanup_failed` |
| `error`、`traceback` | 失败原因与调用栈 |
| `cleanup_errors`、`cleanup_tracebacks` | 关源/HOLD/关闭失败的记录 |
| `points`、`acquisition_count` | 采集次数 |
| `csv_row_count` | 完整落盘的逻辑行数 |
| `invalid_points` | 写 NULL 的点数 |

运行开始时写一次（`status="running"`），结束时用 `tmp → replace` 原子重写。

### 2.1 `voltage_columns` 的三种形态

```jsonc
// PXI：24 列
"ai0_V":      {"channel":0,"harmonic":1,"component":"amplitude","unit":"V","amplitude":"peak"},
"ai0_X_V":    {"channel":0,"harmonic":1,"component":"X", ...},
"ai0_2f_V":   {"channel":0,"harmonic":2,"component":"amplitude", ...},

// 逐点电极表：每列对应一组路由
"V_12-9-11-10": {"route":{"name":"A","columns":[12,9,11,10]},"detail_prefix":"route1_"},

// 直接接线 / 显式 route
"voltage_v": {"kind":"row_route","identity_columns":["route","columns","path","node_id"]}
```

## 3. `data.csv`

### 3.1 公共 27 列（顺序固定）

| # | 列 | 含义 |
|---|---|---|
| 1 | `point` | 逻辑点号（= `logical_point`，兼容别名） |
| 2 | `time_utc` | 本行时间（UTC ISO 8601） |
| 3 | `temperature_setpoint_k` | **已成功下发**的 Probe 设定温度；未知留空（不用实测冒充） |
| 4 | `temperature_k` | Probe 实测温度（采集后回读） |
| 5 | `field_t` | 磁场实测 T |
| 6 | `angle_deg` | 角度（最近一次静止回读） |
| 7 | `current_a` | 固定激励 |
| 8 | `route` | 路由名（直接接线 / A / B …） |
| 9 | `columns` | 四端口映射的 JSON |
| 10 | `path` | 节点路径 |
| 11 | `node_id` | 节点 UUID |
| 12 | `measurement_mode` | `delta` / `pxi` |
| 13 | `measurement_status` | `valid` / `invalid` / `incomplete` / `partial_invalid` |
| 14 | `environment_status` | `ok` / `partial` / `stopped` / `unavailable`（`accepted_by_operator`、`partial_accepted_by_operator` 仅存在于 2026-11-11 之前的旧数据） |
| 15 | `environment_error` | 环境回读失败原因 |
| 16 | `acquisition_start_utc` | 采集开始 |
| 17 | `acquisition_end_utc` | 采集结束 |
| 18 | `vti_k` | VTI 温度 |
| 19 | `pressure_mbar` | 交换气压力 |
| 20 | `environment_read_utc` | 环境回读时刻 |
| 21 | `environment_timing` | `after_point`（PXI/直接）或 `first_route_after_point`（逐点表） |
| 22 | `measurement_error` | 测量失败原因（表级） |
| 23 | `logical_point` | 逻辑点号 |
| 24 | `route_index` | 电极序号（1..N；非逐点表为 0） |
| 25 | `acquisition_index` | 采集序号 |
| 26 | `angle_read_time_unix` | 角度回读的 unix 时间 |
| 27 | `environment_overrides` | 保留列；人工接受已移除，现恒为 `{}`（旧数据里有内容） |

### 3.2 电压列的三种形态

**A. PXI（4 通道 × 6 列 = 24 列）** → 共 **51 列**

```
ai0_V  ai0_X_V  ai0_Y_V  ai0_2f_V  ai0_2f_X_V  ai0_2f_Y_V
ai1_V  ...                                        (ai1–ai3 同构)
```
选 3f 时后缀整体换成 `3f`（`ai0_3f_V` 等），**不会**把 3f 冒名成 2f。单位 V、峰值标度、`幅值 = hypot(X,Y) ≥ 0`。

**B. 逐点电极表** → 27 + N(电压列) + 17N(详情列)

电压列名由电极映射生成，加号表示同口多 pin、减号分隔四口：

```
V_12-9-11-10        I+=12, I−=9, V+=11, V−=10
V_12+11-9-8+7-6     I+=12&11 并联, I−=9, V+=8&7 并联, V−=6
V_12-9-11-10_2      重复接线时第 2 次出现（加 `_2` 后缀区分）
```

两组合时总列数 = 27 + 2 + 17×2 = **63**。

**C. 直接接线 / 显式 route** → 27 + 1 = **28 列**，电压列名 `voltage_v`。

### 3.3 `routeN_` 详情列（17 列 × N）

```
route1_acquisition_index  route1_angle_read_time_unix  route1_time_utc
route1_acquisition_start_utc  route1_acquisition_end_utc  route1_environment_read_utc
route1_temperature_k  route1_vti_k  route1_field_t  route1_pressure_mbar
route1_angle_deg  route1_current_a
route1_measurement_status  route1_measurement_error
route1_environment_status  route1_environment_error  route1_environment_overrides
```

前缀编号对应运行时 `point_routes` 的顺序；`run.json.voltage_columns[*].detail_prefix` 给出对应关系。

### 3.4 `NULL` 与空白（必须分清）

| 值 | 含义 |
|---|---|
| `NULL`（字符串） | **试过**，但该次测量无效（超量程/超时/非数值/过载） |
| 空白 | **没测到**（中途停止、该电极还没遍历到） |
| 数字 | 有效电压（V，峰值） |
| 环境列空白 + `environment_status` | 见状态列解释，不要当 0 |

统计时建议：`measurement_status='valid'` 且电压为数字 → 有效点；`routeN_measurement_status` 才是逐电极的真值，表级 `partial_invalid` **不代表整行作废**。

## 4. `events.jsonl`

一行一个 JSON：`{"time": "...", "event": "<类型>", "data": {...}}`，每条写完 `flush + fsync`。

### 4.1 事件类型

| 事件 | 触发时机 | 关键字段 |
|---|---|---|
| `log` | 每行日志 | `message` |
| `node_start` | 进入节点 | `id`、`path`、`params` |
| `node_done` | 离开节点 | `id`、`path` |
| `set_environment` | 下环境设定 | `axis`、`target`、`params`、`result` |
| `environment_wait` | 等待中每 60 s | `axis`、`target`、`actual`、`action`、`elapsed_s`、`rotation_error` |
| `field_wait` | 磁场进入等待/状态变化 | `target`、`actual`、`action`、`reason` |
| `field_recovered` | 磁场自动续测 | `target`、`actual` |
| `field_not_started` | no-op 且未达容差 | `target`、`actual`、`tolerance`、`result` |
| `environment_accepted` | **停用**（人工接受已移除，仅旧数据存在） | `axis`、`target`、`actual`、`residual`、`wait_id`、`accepted_utc` |
| `angle_recheck` | **停用**（人工复核已移除，仅旧数据存在） | `actual` / `error` |
| `matrix_off_wait` / `_end` | 切换前等待 | `seconds` |
| `matrix_on_wait` / `_end` | 切换后等待 | `seconds` |
| `route_command` | 下发路由 | `name`、`columns` |
| `pxi_reconfigure` | PXI 电流在步骤边界重配 | `current_a`、`path` |
| `pause` / `resume` | 暂停/恢复 | `path` |
| `acquisition` | **单次采集落盘**（先于环境回读） | `point`、`acquisition_index`、`logical_point`、`route_index`、`route`、`columns`、`node_id`、`path`、`data` |
| `point` | 完整行落盘 | 与 CSV 列同名的完整行 |
| `invalid_raw` | 无效读数 | `reason`、`raw_repr`、`route`、`route_index`、`logical_point` |
| `invalid_streak` | 连续无效满 10 的倍数 | `total`、`consecutive` |
| `io_wait` | IO 重试 | `label`、`attempts`、`elapsed_s`、`error`、`path` |
| `failure` | 运行失败 | `error`、`traceback`、`path` |
| `run_end` | 运行收尾 | `status`、`error`、`traceback`、`cleanup_errors`、`points`、`acquisition_count`、`csv_row_count` |

### 4.2 为什么同时有 `acquisition` 和 `point`

- `acquisition` = **一次采集**（细粒度，宽表的一列）；
- `point` = **一整行**（含环境、状态）。

逐点电极表时，同一逻辑点会有 N 条 `acquisition` 和 1 条 `point`。`acquisition.data` 里的 `raw` 保留仪器原始回复（4462 含四通道全部字段与 `daq_metadata`）。

## 5. 从事件恢复数据

```powershell
python audit/recover_points.py "运行目录/events.jsonl" recovered.csv
```

行为：

- 只读 `events.jsonl`，**不覆盖**原 `data.csv`；目标文件已存在则报错（`open('x')`）。
- 输出**逐次采集的长表**（一行一次采集，含 `logical_point`、`route_index`、`acquisition_index`）。
- 遇到不完整的最后一行 JSON 会跳过。
- 环境值**永不伪造**：没有 `point` 事件的采集会标 `environment_status='unavailable'`。
- PXI 通道展开为 `ai{ch}_V` / `ai{ch}_X_V` / `..._2f_V` 等列。

## 6. 读数据的规矩

1. **永远按列名读，不要按列号**——1.7.3→1.7.6 之间列数从 8 变 24 变 48 变 50 变 51。
2. `NULL` 用 `pandas.read_csv(..., na_values=['NULL'])`；空白默认为 NaN，两者语义不同，不要混。
3. 时间列是 UTC；本地时间按需 +8。
4. 逐点电极表优先用 `routeN_*` 状态筛电极，不要用表级状态一刀切。
5. `interval_s` 不是周期，实际时间间隔用 `acquisition_start_utc/end_utc` 相减。
6. `points` 是采集次数，不是宽表行数；宽表行数看 `logical_point` 的最大值或 `csv_row_count`。
