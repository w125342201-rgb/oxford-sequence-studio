# 09 · 测试与验证

> **本文是说明性参考，不是规范。** 规范效力与唯一权威以 [开发规范](../开发规范.md) 为准；本文与规范冲突时，以规范为准并应在规范 §12 登记冲突。

## 1. 跑测试

```powershell
# Windows 中文环境必须先开 UTF-8（原因见 §2）
$env:PYTHONUTF8='1'
python -m unittest discover -s tests -v
```

当前基线（2026-11-11 实测，Python 3.14.7 + numpy 2.5.3）：

```
Ran 200 tests in 10.0s
OK
```

测试**不需要任何仪器**：用 `SimBackend`、仪器替身（fake VISA / fake DAQ / fake Mercury socket）、解析波形和真实算法代码路径。

## 2. ⚠️ 已知环境陷阱：GBK 编码导致 34 项报错

在中文 Windows（默认 locale = GBK）且 Python < 3.15 时，直接运行会得到：

```
Ran 198 tests in 9.5s
FAILED (errors=31)
UnicodeDecodeError: 'gbk' codec can't decode byte 0xac ...
```

原因：多个测试用 `Path.read_text()` / `read_text().splitlines()` 读取含中文的 `events.jsonl`，没有传 `encoding='utf-8'`，于是用了 locale 编码。**产品代码本身都显式指定了 utf-8**，只有测试读文件时偷懒。

三种解法（任选）：

| 方案 | 做法 | 评价 |
|---|---|---|
| 环境变量 | `$env:PYTHONUTF8='1'` | 立刻可用，推荐 |
| 永久设置 | 系统环境变量加 `PYTHONUTF8=1` | 影响本机所有 Python |
| 改测试 | 给每个 `read_text()` 传 `encoding='utf-8'` | 最彻底，见 [10-开发指南](10-开发指南.md) 待办 |

这**不是产品缺陷**（程序自己写文件都带编码），但会让新人以为测试坏了。建议在 CI/脚本里固定 `PYTHONUTF8=1`。

## 4. 示例模拟（手工验证）

```powershell
python run_simulation.py examples/01_T_B_electrodes.json
# → Points: 30   （3 温度 × 5 磁场 × 2 电极组合；逐点电极表，63 列）

python run_simulation.py examples/02_angle_1deg_MR_PXI.json
# → Points: 9    （PXI 四通道，每 1° 一次；51 列）
```

输出在 `./simulation_data/<时间戳>_<hex>/`。可用于快速确认：

- 列数对不对（51 / 63 / 28）；
- `events.jsonl` 里有 `acquisition`、`point`、`run_end`；
- `run.json.status == "completed"`，`acquisition_count` 与行数对得上。

## 6. 这些测试**不能**证明什么

| 已证明 | 未证明 |
|---|---|
| 控制流、状态机、迁移、校验规则 | 真实仪器时序、继电器机械动作 |
| 解调数学（解析输入，误差 ~1e−13 V） | 实际 ADC/滤波/线缆相移 |
| CSV/事件字段与列名 | Excel / pandas 具体读取行为（列名稳定，列号会变） |
| 仪器替身上的调用顺序 | 6221 固件版本差异、VISA 驱动版本差异 |
| 无显示环境下的 Tk 逻辑 | Windows 实绘、高 DPI 缩放、字体 |

## 7. 首次实机验收清单（按顺序做，不要跳）

1. **空载连接**：模拟模式跑通 → 真实模式仅连接 → 看日志里的 IDN、确认 6221 输出 OFF、矩阵全断开。
2. **旋转杆**：手动静止回读角度 → 小角度（±5°）运动 → 确认方向与读数符号一致（曾两次改过方向位约定）。
3. **磁场小步长**：设 0.05 T 步长、步进容差 0.0002 T，确认不会"未起励却判到位"；观察 `field_wait` / `field_not_started`。
4. **Delta 归一化**：接**已知标准电阻**，比较 6221 显示、CSV 的 `voltage_v`、`V/I`；确认没有历史"除 2"残留。
5. **矩阵四端**：用标准电阻逐组切换，确认 `V_...` 列与物理接线一致；确认关源确认失败时程序拒绝切换。
6. **4462 1f**：标准电阻 + 已知电流，比较幅值与相位稳定性；确认 24 列都写入。
7. **4462 2f/3f**：注入**已知相干**的 2f 或 3f 信号，确认符号与幅值；再看热测量默认相位是否把理想信号放在 X 上。
8. **量程**：同一稳定信号分别用 ±316 mV 与 ±1 V 档，电压应在设备不确定度内一致（差异说明增益/校准问题）。
9. **长跑**：温度扫描 + 磁场扫描 + 逐点电极表跑 30 分钟，检查 `invalid_points`、`csv_row_count`、`environment_status`。
10. **异常演练**：拔网线（通信超时）、电源前面板暂停、中途停止——确认程序等待/停止行为符合 [06-执行引擎](06-执行引擎.md)。

每完成一项，把 `run.json` + `events.jsonl` 存档，作为该台设备的验收证据。

## 8. 回归报告的读法

`audit/regression_1.7.x.txt` 是**当时**的结果快照。版本升级后不要引用旧报告当"当前通过"，应重新跑：

```powershell
$env:PYTHONUTF8='1'; python -m unittest discover -s tests -v 2>&1 | Tee-Object audit/regression_<版本>.txt
```

（历史报告里 `201 项` / `178 项` 等数字随版本变化，属正常现象；当前是 200 项。）
